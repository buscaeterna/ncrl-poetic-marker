# Разметчик стихов НКРЯ

Локальный stack уже поддерживает пакетный PDF-импорт и OCR Tesseract `rus+eng`.
Локальная пакетная расстановка ударений на Silero Stress 1.4 описана в
[`docs/AUTOMATIC_STRESS_RU.md`](docs/AUTOMATIC_STRESS_RU.md). Модель устанавливается
явно, работает на CPU и сохраняет предложения отдельно до ручного принятия.

Браузерный редактор и валидатор разметки с автономной GitHub Pages-версией и локальным полным режимом.

## Локальный запуск и безопасность

Скопируйте `.env.example` в `.env` при необходимости настройки и выполните `docker compose up --build`, затем откройте <http://localhost:8080>. Gateway по умолчанию публикуется **только на `127.0.0.1`**. Авторизации пока нет: не устанавливайте `NCRL_BIND_ADDRESS=0.0.0.0` и не открывайте приложение в интернет без самостоятельно настроенной защиты.

Полный stack: nginx `gateway`, Next.js `web`, FastAPI `api`, PostgreSQL `db`, одноразовые Alembic-миграции `migrate` и отдельный `worker`. Только gateway публикует порт хоста.

## Локальные и серверные данные

IndexedDB автоматически хранит текущий браузерный черновик и продолжает работать при недоступном API. PostgreSQL хранит явно созданные через кнопку **«Проекты»** полные JSONB-снимки workspace. Текст не отправляется на сервер до нажатия создания или сохранения проекта. Открытие серверной копии требует подтверждения и также сохраняет её в IndexedDB. Оптимистическая revision предотвращает потерю более свежей серверной версии.

Кнопка «Проекты» позволяет создать, открыть, сохранить/переименовать и удалить проект, увидеть revision, скачать или импортировать проверяемую JSON-резервную копию, а также поставить безопасное задание «Сводка проекта» и отменить его в очереди. `workspace_summary` считает корпуса, произведения, стихотворные строки, изменённые произведения и статусы; это не автоматическая разметка или метрический анализ.

PostgreSQL использует named volume `ncrl_data`: обычный `docker compose down` сохраняет проекты. **`docker compose down -v` необратимо удаляет все серверные проекты и задания** — сначала скачайте JSON-копии.

GitHub Pages остаётся полностью статическим: серверной кнопки и API-запросов проектов там нет, используется IndexedDB. Телеметрии, внешних/облачных API нет. PDF/OCR и автоматические ударения доступны только в локальном stack; метрический анализ и универсальные нейросети пока не реализованы.

## Разработка

Node.js 22: `npm ci`, `npm test`, `npm run lint`, `npm run build`, `npm run build:pages`. Python 3.12: `python -m pip install -e "backend[test]"`, `python -m pytest backend/tests`. API: `/api/v1/ready`, `/api/v1/capabilities`, `/api/docs`. Максимум запроса workspace — 20 MiB (FastAPI и nginx возвращают 413).

## PDF и локальный OCR

Полный локальный режим поддерживает пакетную загрузку PDF и обязательную постраничную проверку перед импортом. Цифровой текст извлекается pypdf, а страницы рендерятся pypdfium2; для страниц без пригодного слоя выполняется CPU-OCR Tesseract (`rus+eng`). PDF и preview остаются в named volume `ncrl_files`, а метаданные и исправления — в PostgreSQL. Данные не отправляются в облако; GitHub Pages не показывает эту функцию.

Docker Desktop 4+ или совместимый Docker Engine поддерживаются на Windows, macOS и Linux (`linux/amd64`, `linux/arm64`); GPU не требуется. Образ стал больше из-за OCR. Лимиты: `NCRL_MAX_PDF_BYTES` (200 MiB), `NCRL_MAX_PDF_PAGES` (1000), `NCRL_PDF_RENDER_DPI`, `NCRL_PDF_MAX_PIXELS`, `NCRL_OCR_PAGE_TIMEOUT_SECONDS`.

Резервная копия включает дамп `docker compose exec db pg_dump -U ncrl ncrl` и архивы volumes `ncrl_files` и `ncrl_models`. Удаление проекта/источника удаляет связанные файлы. OCR не является корректурой: колонки, колонтитулы, переносы, дореформенная орфография, плохой контраст и сканы могут распознаваться ошибочно. Каждую страницу, затем автора, заголовки и границы произведений требуется проверить вручную. Имя PDF не принимается за автора.
