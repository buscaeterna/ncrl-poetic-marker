# Автоматические ударения: локальная установка и проверка

> Функция находится в разработке: пакетная серверная основа и ручное принятие
> данных реализованы, но production-модель не поставляется до проверки лицензии
> весов. Встроенный тестовый словарь не заменяет филологическую проверку.

## Запуск

На Windows/macOS установите Docker Desktop; на Linux — Docker Engine и Compose
plugin. Выполните `docker compose up --build` и откройте
<http://127.0.0.1:8080>. GPU и внешняя передача текста не используются.

Модели устанавливаются только явным действием пользователя. Будущий экран
покажет имя, версию, размер, SHA-256 и ход загрузки; офлайн-файл должен пройти
те же проверки manifest. Незавершённый `.part` не является установленной
моделью. Только файлы модели загружаются из сети — тексты компьютер не покидают.

Пакет выбирается по произведениям, сохраняет их порядок и revision проекта.
Предложения следует сравнить с оригиналом: принять слово/строку, отклонить или
исправить вручную. Непринятые и устаревшие предложения в TXT/HTML не попадают.
Омографы, неизвестные/OCR-слова, имена, сокращения и дореформенная орфография
требуют внимания. `ё` считается ударной без добавления `` ` ``.

## Данные и обслуживание

Для резервной копии остановите stack и скопируйте Docker volumes `ncrl_data`,
`ncrl_files`, `ncrl_models`. При обновлении используйте `docker compose pull`
и `docker compose up --build`; не запускайте `down -v`. Полное удаление:
`docker compose down -v`. Ориентир без production-весов: 2 GiB RAM и 5 GiB
диска; точные требования модели будут опубликованы в manifest.
