# Архитектура

## Назначение

Проект развивается вокруг **единого веб-интерфейса** разметки. Один и тот же интерфейс должен работать в облегчённой статической публикации и в будущей полной локальной/self-hosted-системе, чтобы форматы данных и рабочий процесс пользователя не расходились.

## Текущий облегчённый режим: GitHub Pages

GitHub Pages запускает только клиентскую часть. Она предоставляет редактор, импорт и экспорт, работу с UTF-8 и Windows-1251, очередь, предварительное разделение сырого текста и хранение в IndexedDB. Это полезный автономный режим без обязательной подписки или внешнего API.

GitHub Pages **не является полной серверной версией**: статический хостинг не выполняет серверные задания, OCR, модели или многопользовательскую синхронизацию.

## Будущий полный локальный/self-hosted-режим

Локальный движок планируется для Windows, macOS и Linux на архитектурах `amd64` и `arm64`. Интерфейс будет доступен через браузер с любой современной ОС, способной подключиться к развёрнутому экземпляру.

Целевая серверная схема предусматривает следующие будущие компоненты:

- API на FastAPI;
- PostgreSQL для серверного рабочего пространства;
- очередь заданий и отдельный worker;
- конвейер PDF/OCR;
- локальные модели для языковых задач и анализа.

Эти компоненты описывают направление развития и пока отсутствуют в репозитории. CPU будет обязательным, полностью поддерживаемым режимом исполнения; GPU — только опциональным ускорением. Базовая локальная работа не должна требовать подписки, облачного сервиса или внешнего API.

## Границы данных и предметные правила

- **Один файл не равен одному стихотворению.** Импорт обязан допускать несколько произведений в одном исходном файле и этап предварительного разделения.
- **Имя файла не определяет автора.** Авторство устанавливается по данным корпуса и действиям пользователя, а не выводится автоматически из имени файла.
- Формат корпусов и браузерная пользовательская логика должны оставаться совместимыми между режимами.
- Серверные возможности должны расширять единый интерфейс, а не создавать отдельный несовместимый редактор.
