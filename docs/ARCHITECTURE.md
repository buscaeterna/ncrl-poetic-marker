# Архитектура

## Единый интерфейс, два runtime-режима

Исходный код Next.js один. Build-time переменная `NEXT_PUBLIC_RUNTIME_MODE` равна `static` для GitHub Pages и `full` в Docker. Pages-сборка использует `output: export`, repository `basePath` и IndexedDB. Production-сборка использует Next.js standalone server. Статический режим вообще не запрашивает API; полный режим делает один health-запрос с коротким timeout, а ошибка не влияет на редактор.

## Локальный stack

`compose.yaml` поднимает три сервиса:

1. `web` — non-root production Next.js;
2. `api` — non-root FastAPI/Uvicorn с типизированными Pydantic-ответами;
3. `gateway` — nginx и единственная внешняя точка `http://localhost:8080`.

Nginx сохраняет путь при проксировании `/api/` на API и направляет всё остальное в web. Gateway ждёт healthcheck API. Uvicorn получает стандартный сигнал остановки Compose и корректно завершает процесс. Используются официальные multi-architecture базовые образы.

## Данные и границы этапа

Документы, очередь и черновики остаются в IndexedDB браузера; тексты не отправляются локальному API автоматически и никогда не отправляются внешним сервисам. API сейчас сообщает только здоровье и честный набор capabilities (все будущие функции `false`). PostgreSQL, Redis, worker, авторизация и совместная работа отсутствуют.

Один файл может содержать несколько произведений, а имя файла не определяет автора. PDF/OCR, автоматические ударения, метрический анализ и локальная модель не реализованы. Они будут добавляться последовательными слоями поверх созданного локального API с сохранением автономного редактора.
